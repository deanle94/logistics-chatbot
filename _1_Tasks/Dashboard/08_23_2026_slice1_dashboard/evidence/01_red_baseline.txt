01_red_baseline.txt — the Slice 1 evals fail against code that does not compute the right answer
================================================================================================
Spec step 1: "Write them so they FAIL against today's code."

An earlier version of this file achieved red by renaming the Slice 1 modules aside, so the
eval modules failed to IMPORT. That proves the tests exist. It does not prove they can tell a
right answer from a wrong one — a test asserting `assert True` would have gone red the same way.

This version plants a real defect instead, in two halves, so every assertion RUNS and fails on
a VALUE. Both halves are re-runnable and both revert themselves in a shell trap, so an
interrupted run cannot leave the defect behind. The scripts are in the task scratchpad:
red_calc.sh and red_browser.sh.

================================================================================
HALF 1 of 2 — the backend evals (S1.1, S1.2, S1.3, S1.4)
================================================================================
Planted defect: every entry in calculator/metrics.py's METRIC_EXPRESSIONS is pointed at the
naive "count every row" expression. Every module still imports; every formula is now wrong.

This is the sharpest single lever available, because METRIC_EXPRESSIONS is the one place a
business definition lives (architecture Decision 1). If the definitions could be broken from
anywhere else, that would itself be the bug.
